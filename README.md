# Force Duo 简体中文兼容恢复测试版 1.3.5

本仓库基于 [34306/ForceDuoApp](https://github.com/34306/ForceDuoApp) 固定提交 `5b65200015f7ed0a0fdf34708bd857e4a34e1f80`，叠加简体中文界面与游戏兼容性恢复入口。

GitHub Actions 在 Xcode 27 环境编译未签名 IPA，产物位于 Actions 页面。下载后用 Sideloadly 等工具签名安装，务必保留原应用的 App Groups 权限。

Force Duo 只修改 LaunchServices 的 SDK 记录，无法改写游戏内的音频或画面代码。游戏黑屏、静音时可恢复该游戏的原始 SDK，应用修改并重启设备。此功能是否能处理特定游戏仍需真机验证。

1.3.5 修正单独恢复的误报。即使列表已经显示原始 SDK，也会重新核对系统缓存，再判断是否需要写入。

1.3.4 在盾牌菜单增加“仅恢复此应用，测试声音”。优先使用与当前安装匹配的原始 SDK 记录，缺失时从安装文件读取。该按钮只应用这一款游戏的恢复，保留其他应用的待应用修改。重启后分别测试外屏播放时展开到内屏，以及下拉并收起通知中心。

1.3.3 将待恢复操作与兼容保护分别保存。解除保护后，已排队的恢复仍会保留，重开 Force Duo 或点“全选”也不会取消。手动打开该应用的开关可以取消待恢复，并保留之前选择的试验 SDK。

1.3.2 修正从安装文件找回的原始 SDK 被旧记录清掉的问题。生效前会再核对缓存版本。“全部取消选择”只保存一次。诊断导出会报告保存结果，导出后仍可查看上一次写入的耗时。缓存写入遇到部分写入会继续完成，无法完成时回滚已尝试的记录。备份只在验证成功后轮换。

1.3.1 在写入前重新检查每个目标的安装容器和 SDK。应用在列表打开后更新或卸载时，整批写入会停止并提示刷新。具有安装容器记录的恢复点只适用于对应安装，兼容保护仍按应用保留。写入完成但读回失败时，下次加载会核对已经写入的试验版本。

本次以 `audio-wake-trial` / `sdk-recovery` 的 `dbb8bca` 为基线，修正兼容恢复和加载流程：

- 每个应用增加盾牌入口，针对通知中心、控制中心、合盖 / 展开后无声和启动黑屏，找回安装程序中记录的编译 SDK，再由用户点“应用”恢复。
- 恢复时保存兼容保护，覆盖安装、重启工具后仍保留；“全选”、开关和 SDK 试验均不能再次启用受保护的应用。解除保护后才可手动启用。
- 当前记录已经等于原始 SDK 时，不再留下无法应用的恢复状态；写入完成但读回失败时，下次读取会核对并完成恢复，保护仍保留。
- 图标下载从应用扫描 / 写入流程中分离，网络超时不再让列表操作一直禁用；折叠造成视图重新出现时不重复扫描。此项是工具自身加载改进，不代表目标应用黑屏已修复。
- 写入系统缓存前必须成功备份，写入时核对当前缓存文件；移除持锁期间对活动缓存的重复打开，写入失败后会尝试恢复每条记录。桌面卡顿的根因需要真机复现确认。

使用方法：保持原签名应用标识覆盖安装，在“全部”找到受影响应用 → 盾牌 → “从安装文件找回原始 SDK” → “应用” → 重启。已保护的应用可在“兼容”分类找到。恢复会取消该应用的强制适配；本版本不承诺同时保留强制全屏并解决无声。

验证范围与真机步骤见 [RECOVERY_TEST.md](RECOVERY_TEST.md)。未签名 IPA 在本次分支的 Actions 构建产物 `ForceDuo-compatibility-recovery-unsigned-IPA` 中。

## 替换应用图标

将原图以 `ForceDuoIcon.png` 的文件名上传到仓库的 `assets/` 目录。每次上传会自动重新构建 IPA；构建时只按苹果图标要求缩放到 1024×1024，不重绘图案。上传后到 Actions 页面下载最新构建产物。
